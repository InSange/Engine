> 최종 수정: 2026-03-29

## 1. 게임 개요

| 항목 | 내용 |
|------|------|
| 장르 | 3D 1인칭 협동 액션 |
| 레퍼런스 | R.E.P.O. (카오스 협동 / 1인칭) |
| 플레이어 수 | 2인 온라인 (Steam) |
| 플랫폼 | PC (Steam) |
| 네트워크 | Host-Client (Listen Server) / Steam Relay |
| 핵심 키워드 | 저주, 협력, 위임, 퍼즐 액션 |

### 한 줄 컨셉
> "저주받은 두 용사가 저주를 무기로 삼아 최종 보스를 처치한다"

### 게임 루프 요약
```
스테이지 입장
    → 저주 부여
    → 저주 위임/배분 전략
    → 스테이지 클리어 조건 달성
    → 다음 스테이지 (저주 누적)
    → 보스 처치
```

### 2-1. 저주 시스템 (Curse System)

#### 부여 규칙 (확정)
| 항목 | 내용 |
|------|------|
| 스테이지 시작 시 부여 | 플레이어 1인당 1~5개 (난이도별) |
| 초반 스테이지 | 플레이어 1인당 1개씩 |
| 후반 스테이지 | 플레이어 1인당 최대 5개 |
| 위임 후 최대 스택 | 사실상 무제한 (10개 이상도 가능) |
| 저주 타입 | 수치 변형 + 행동 제약 혼합 |

#### 저주 유형 분류 (확정)
```
[수치 변형형]                    [행동 제약형]
  - 이동속도 변경                  - 특정 행동 불가
  - 크기 변경                      - 강제 행동 발생
  - 데미지 배율 변경               - 시야/감각 제한
  - HP 최대치 변경                 - 조작 반전 등
```

#### 스테이지별 저주 배분 방식 (확정)
```
[필수 저주 스테이지]
  - 클리어 조건에 특정 저주 필요
  - 두 플레이어 중 최소 1명에게 반드시 해당 저주 부여
  - 예: 좁은 구멍 통과 스테이지 → 둘 중 하나에게 반드시 "소형화" 부여

[일반 저주 스테이지]
  - 저주 풀(Pool)에서 무작위 부여
  - 스테이지 난이도에 따라 개수 결정
```

#### 저주 예시 목록 (초안 — 추후 확장)
| 저주 이름 | 타입 | 효과 | 역활용 방법 |
|-----------|------|------|------------|
| 무거운 몸 | 수치 | 이동속도 -50% | 넉백 저항 |
| 소형화 | 수치 | 크기 0.3배 | 좁은 구멍 통과 |
| 거인화 | 수치 | 크기 3배 | 광역 공격, 통로 막기 |
| 유리몸 | 수치 | 받는 피해 3배 | 특정 오브젝트 파괴 |
| 불꽃 몸 | 수치+행동 | 지속 피해, 물 즉사 | 얼음 장애물 파괴 |
| 투명화 | 행동 | 아군 시야에서 사라짐 | 특정 적 감지 회피 |
| 자석 | 행동 | 금속에 달라붙음 | 벽 이동, 기믹 발동 |
| 강제 점프 | 행동 | 5초마다 강제 점프 | 타이밍 활용 |
| 시야 반전 | 행동 | 상하 시야 반전 | - |
| 조작 반전 | 행동 | 좌우 이동 반전 | 숙련 후 정상화 |

> 총 저주 개수 목표: 20~30개 (미확정)

### 2-2. 저주 위임 (Curse Transfer)

**규칙:**
- 자신의 저주 중 하나를 **상대방에게 위임** 가능
- 위임 = 내 저주가 사라지고 상대의 저주 목록에 추가됨
- 상대방은 저주가 **+1** 증가

**전략 포인트:**
- 단순히 짐 떠넘기기가 아닌 **전략적 배분**
- 상대가 감당 가능한 한계 파악 필요
- 클리어 조건 저주를 가진 플레이어가 최적 포지션을 잡아야 함

**위임 규칙 (확정):**
- 제한 없음 — 언제든지 자유 위임 가능
- 의도된 트롤링 허용 (혈압 마라톤 방식)
- 트롤링 → 클리어 불가 → 결국 협력 강제 → 플레이타임 증가

**트롤링 시나리오 예시:**
```
A가 저주를 B에게 몰아줌 → B 전투 불능
→ A 혼자 클리어 불가 → 자연스럽게 협력 유도
```

### 2-3. 스테이지 클리어 조건

#### 일반 스테이지
- 저주 영향을 받은 상태로 목표 달성 (적 처치, 도착 등)
- 저주 조합에 따라 클리어 루트가 달라짐

#### 특수 스테이지 (저주 기믹 스테이지)
- **클리어에 특정 저주 필수**
- 해당 저주는 반드시 두 플레이어 중 **한 명에게 존재**하도록 설계
- 어떤 저주 배분 상태여도 클리어 불가능한 경우 없음 (위임으로 해결 가능)

**예시:**
```
[스테이지: 얼음 다리]
조건: 얼음 블록을 녹여야 통과 가능
필요 저주: '불꽃 몸'
→ 두 플레이어 중 한 명에게 반드시 '불꽃 몸' 부여
→ 만약 다른 플레이어에게 있다면 위임으로 해결
```

### 스테이지 구조 (확정)

```
[Safe Area - 출발 지점]
    ↓  (플레이어 입장)
[Danger Area]

    - 필드에 랜덤 아이템 박스 타이머 드랍
```

## 7-1. 엔진 확장 요구사항 (Unity 에셋 파이프라인)
> KayKit 두 팩 모두 동일한 파이프라인으로 처리 가능 (같은 시리즈, 동일 포맷)

KayKit 에셋은 Unity 패키지 형태이므로 NuNuEngine에서 사용하려면 변환 파이프라인이 필요합니다.

### Unity 에셋 → NuNuEngine 변환 흐름
```
Unity Editor
    → FBX 익스포트 (모델 + 애니메이션)
    → PNG/TGA 익스포트 (텍스처)
        ↓
NuNuEngine
    → FBX 로더 (Assimp 라이브러리)
    → 텍스처 로더 (DirectXTex 또는 stb_image)
    → 머터리얼 시스템 (PBR 셰이더)
    → 애니메이션 시스템 (스켈레탈 애니메이션)
```

### 엔진에 추가해야 할 기능
| 기능 | 라이브러리 | 우선순위 |
|------|-----------|---------|
| FBX/glTF 로딩 | Assimp | 높음 |
| 텍스처 로딩 | DirectXTex | 높음 |
| 스켈레탈 애니메이션 | 자체 구현 (Assimp 데이터 활용) | 중간 |
| PBR 머터리얼 | HLSL 셰이더 | 중간 |

> KayKit 에셋은 `.fbx` + `.png` 형태로 Unity에서 익스포트 가능.
> Unity 라이선스 확인 필요 — Personal/Pro 모두 타 엔진 익스포트 허용.
